Private Firewall — Help

Private Firewall is a live dashboard and control panel for the firewall that is already built into your computer. It never replaces the system firewall — it watches it, explains it, and lets you act on it. If this app is closed or crashes, your firewall keeps protecting you exactly as configured (fail-open design). Everything runs on your own machine; nothing is sent anywhere.

Who is enforcing the rules

—

  • Windows: rules are enforced in the kernel by Windows Firewall (the Windows Filtering Platform, WFP). Private Firewall writes its rules into a dedicated group named PrivateFirewall, so everything it creates can be reviewed — and removed — in one place.
  • Linux / Quick OS: rules are enforced by ufw (the Uncomplicated Firewall, on netfilter). Quick OS ships ufw enabled with safe defaults: incoming connections blocked, outgoing allowed, remote login (SSH) allowed. Every rule this app creates carries a PFW comment; the system's own rules are listed too (marked system) but can never be removed from here.

Rules basics

  • Allow lets traffic through, Block/Deny drops it. Inbound is traffic coming to your machine, Outbound is what your apps send out.
  • Per-app vs per-port: Windows can allow or block a specific program (per-.exe rules — a WFP feature). Linux firewalls filter by port, address and application profile, never by program. That is why the “block app” button exists only on Windows, and the port/profile rule form only on Linux. This is an honest platform difference, not a missing button.
  • Block an IP blocks all traffic to and from that address. Automatic blocks (port scans, brute force) expire on their own.
  • Lockdown (zero-trust outbound) blocks all outgoing traffic except what you explicitly allow. DNS and DHCP stay open so the network itself keeps working. Expect apps to stop reaching the internet until you allow them.
  • Network profiles (Public / Private / Domain) are a Windows concept: the app automatically tightens alerting on untrusted (Public) Wi-Fi. Linux has no equivalent, so the profile pill is hidden there.
  • Rule order (Linux): the first matching rule wins. Blocks created here are placed at the top, above the system's allows.

Safe defaults

  • This app never disables the system firewall. On Linux the privileged helper refuses to run ufw disable/reset at all, even if asked. Quick OS's shipped policy (deny incoming, allow outgoing, SSH allowed) stays in place.
  • Everything the app creates is tagged (rule group on Windows, PFW comments on Linux) so it can be reverted cleanly; the Windows uninstaller removes every rule it added.
  • The dashboard listens only on 127.0.0.1 and requires the launch token — it is not reachable from the network.

Alerts & notifications — off by default

  • Firewalls see constant background noise, so popup notifications are muted until you turn them on (Settings → Desktop notifications). Muting affects popups only: the firewall keeps enforcing rules, and every alert, drop and event is always recorded right here on the dashboard — the header shows “Protection active — notifications off”.
  • When you enable popups, conservative defaults apply: only serious and critical alerts, only from internet sources. You can widen this (severity threshold, local-network sources) in the same panel.
  • Even with notifications on, link-local / ICMPv6 / multicast background traffic stays below the alert line — it is classified as background, never as an attack.

Start at login & the tray

  • After you first set the app up (the first time it gains admin), it starts at login automatically — tray icon only, no window. Toggle this in Settings → “start at login”.
  • Enforcement never depends on the app. The system firewall (ufw / Windows Firewall) enforces your rules from boot whether or not Private Firewall is running; the autostarted app is the monitoring and control surface. The tray dot shows the real state: green = protection active, red = the system firewall is off.
  • No password prompt at login. The app starts in read-only monitoring mode; the first action that actually changes the firewall (add/remove rule, lockdown, kill) raises the system authorization prompt, once per session.
  • Launching the app again while it is running simply brings up the existing dashboard — from the tray, use Open Dashboard.

Troubleshooting

  • “Engine is running unelevated / read-only”: on Windows, relaunch from the Start Menu shortcut (it elevates via UAC). On Linux, click Enable admin in the banner and approve the system prompt.
  • A rule doesn't seem to take effect: connections that were already open keep running until they close — use kill on the connection row or wait. Check the rule actually appears in the rules list. On Linux remember the first matching rule wins.
  • Locked out of remote login (SSH) on Linux: Private Firewall never removes the system SSH rule and cannot disable ufw, so a lockout can only come from a rule you added — an IP block covering your own address, or a deny on port 22. Remove it from the rules list. If you are already locked out, from the machine's own console run sudo ufw status numbered then sudo ufw delete <number>.
  • “The system firewall is inactive” (Linux): enable it from your system's security settings, or from a console: sudo ufw enable. Quick OS ships it enabled.
  • Why do I see blocked local traffic in the feed? Home networks are chatty: routers, phones, TVs and virtual adapters constantly announce themselves (IPv6 neighbor discovery, multicast, IGMP). A deny-incoming firewall drops that chatter as a matter of course. Private Firewall shows it dimmed as “local background traffic” and never counts it as an attack — alerts are reserved for real patterns such as port scans or repeated connection attempts from routable addresses.
  • “Blocked today” stays at 0 / empty feed: the blocked-connection feed needs firewall logging: the Windows installer turns on drop-logging; on Linux ufw's default logging (low) is enough — if it was turned off, alerts based on drops can't fire either.
  • The app won't start a second time: only one engine runs per machine — find the running one in the tray, or open http://127.0.0.1:58730.
